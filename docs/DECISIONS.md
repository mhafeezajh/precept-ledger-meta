# Decisions

Each entry: ID, decision, alternatives rejected, why, date. Newest decisions go at the bottom of each table.
Entries marked **default** were adopted from Claude's recommendation when the owner said "start building"
without answering the question. The owner can overturn them; the code changes with them.

## Hard rules (from the kickoff, section 0)

These are not up for trade-off. Every module is checked against them before it is called done.

| ID | Rule |
| --- | --- |
| H1 | **New work only.** Every line of code is written from Oct 27, 2026 onward; the demo shows only work built during the event. No code from `precept-insight` or any other private source. The README's "Built during the hackathon" section lists every component. |
| H2 | **Commercial core stays out.** No commercial Gate runtime, bundle signing, SPIFFE/mTLS or Terraform. |
| H3 | **Code decides, models extract.** No model call in the allow / deny / escalate path, in verification or in the claim checker. |
| H4 | **Fail closed.** Ledger write fails → action does not run. Model output fails schema or proof checks → rejected, never silently repaired. |
| H5 | **Write before effect.** An allowed tool call reaches the tool only after its decision record has a ledger receipt. |
| H6 | **Meta models only, through LiteLLM, Standard mode.** Contributor mode is never enabled. |
| H7 | **Public repo, Apache-2.0, from day 1.** Small, frequent commits; history is evidence of new work. |

## Ledger record format (step 1, Oct 27)

These resolve conflicts C1–C9 found between the kickoff, `docs/ARCHITECTURE.md` and the engineering skill.

| ID | Decision | Rejected | Why | Date |
| --- | --- | --- | --- | --- |
| D9 (C1, **default**) | The producer signs the record **without** `seq`, `prev_hash` and `producer.sig`. The ledger assigns `seq` and `prev_hash`; the chain and leaf hashes cover the full stored record including the signature. | Producer signs the whole record minus `sig` (as ARCHITECTURE first read) | The producer cannot know `seq`/`prev_hash` without locking the ledger head, which breaks concurrent appends. Consequence: the operator can reorder or drop records and recompute the chain without breaking producer signatures; that attack is caught by receipts held by producers (signed `seq` + `chain_hash`) and, from day 2–3, by checkpoints and witnesses. Tested in the tamper suite. | 2026-10-27 |
| D10 (C2, **default**) | Envelopes carry `alg`: `producer.alg` on records, top-level `alg` on receipts. Only `ed25519` is accepted. | No `alg` field | Algorithm agility (skill §4); a later hybrid with ML-DSA needs no hash change. Unknown `alg` is rejected, never guessed. | 2026-10-27 |
| D11 (C3, **default**) | Receipt = `{v, alg, stream, record_id, seq, leaf_hash, chain_hash, received_at, key_id, sig}`, table `receipt`. | Kickoff's `ledger_receipt(record_id, seq, hash, signature, key_id)` | Follows ARCHITECTURE; `stream` added because `seq` is only unique within a stream; `v`/`alg`/`key_id` make the receipt self-describing. | 2026-10-27 |
| D12 (C4, **default**) | Record types are dotted names: `gate.decision`, `gate.approval`, `policy.approve`, `qa.answer`, … | Bare `decision` | Matches ARCHITECTURE; namespaces by producing component. | 2026-10-27 |
| D13 (C5, **default**) | Test vectors live in `tests/vectors/`. | `verify/testdata/` | Skill §6; one place for all vectors. | 2026-10-27 |
| D14 (C6, **default**) | `docs/ARCHITECTURE.md` is kept as exported and gets a change log; it is not regenerated from kickoff section 2. | Rewrite it from the kickoff | The export is the more detailed source of truth. | 2026-10-27 |
| D15 (C7, **default**) | Cut order follows ARCHITECTURE (on-prem → OpenTimestamps → MCP proxy → learner tightening). mypy `--strict` uses the skill's wider scope (`ledger verify witness claims gate anchor`, plus `common`). | Skill's cut order; kickoff's narrower mypy scope | ARCHITECTURE is the source of truth for plan; stricter typing costs nothing. | 2026-10-27 |
| D16 (C8, **default**) | First record in a stream has `seq = 1` and `prev_hash = h_0` (32 zero bytes). Merkle leaf index = `seq − 1`. | `seq = 0` first | Matches the formula's `h_0` genesis value. | 2026-10-27 |
| D17 (C9, **default**) | Records allow integers only, within ±(2^53 − 1); no floats. Amounts are whole dollars as in the existing examples. | Floats; decimal strings; integer cents | Floats are risky for money and for cross-language canonicalization. Whole dollars match every example in ARCHITECTURE. | 2026-10-27 |
| D18 | Signing inputs get context strings: records `"PL-record-v1\x00"`, receipts `"PL-receipt-v1\x00"`, prepended to the JCS bytes. | Sign bare JCS bytes | Domain separation (skill §4): a record signature can never be replayed as a receipt signature or vice versa. ARCHITECTURE did not name these strings; added to its change log. | 2026-10-27 |
| D19 | `key_id = "ed25519:" + hex(SHA-256(raw 32-byte public key))`. Hashes and signatures are standard base64 with padding, and must be the canonical encoding (re-encoding must give the same text). | Base64url; hex for hashes | ARCHITECTURE shows `ed25519:9f2c…` (hex) and `base64...`; C2SP notes use standard base64. Canonical-encoding check closes the gap where two base64 strings decode to the same bytes, so a one-byte edit can never go unnoticed. | 2026-10-27 |
| D20 | Exports and the verifier read records as canonical JSON lines; a line that is not byte-identical to its own canonical form is rejected at its sequence. | Accept any JSON that parses | Makes "any single-byte edit fails at its sequence" hold for every byte, including whitespace and escapes. | 2026-10-27 |
| D21 | Postgres stores records as typed columns plus `body jsonb`, and the record is rebuilt from those columns for verification. | Store the canonical bytes as an authoritative blob | Demo beat 4 edits a row directly; that edit must change what the verifier sees. A blob next to editable columns would hide the edit. | 2026-10-27 |
| D22 | Appends are serialized per stream with `pg_advisory_xact_lock`, backed by `UNIQUE (stream, seq)` and `UNIQUE (record_id)`. | `SERIALIZABLE` retries; a head table with `FOR UPDATE` | Simplest correct gap-free sequence; the unique constraints make any bug fail loudly. | 2026-10-27 |
| D23 | The ledger store is async (`psycopg` 3 async pool); `Ledger.append` is a coroutine. | Sync store now, async later | FastAPI handlers are async and must not block (skill §3); avoids a rewrite on day 2. | 2026-10-27 |
| D24 | ULIDs are generated by `common/ids.py` (20 lines) with an injected clock and `secrets`. | `python-ulid` | Removes a dependency; keeps time injectable and randomness on `secrets` (skill §3, §4). | 2026-10-27 |

## Witnesses (step 6, Oct 27)

| ID | Decision | Rejected | Why | Date |
| --- | --- | --- | --- | --- |
| D38 | Cosignatures are C2SP tlog-cosignature `cosignature/v1` with Ed25519. The signed message is `"cosignature/v1\ntime <t>\n"` followed by the checkpoint body. The key hash uses signature type 0x04. The line value is `key hash ‖ uint64_be(t) ‖ signature`, appended to the checkpoint note as another signature line. The format and the tlog-witness request body live in the pure `ledger/cosignature.py`, which the witnesses, the ledger and `pl-verify` all import. | Signing a JSON `{checkpoint, timestamp}` (ARCHITECTURE wording); putting the code under `witness/` | D4 asks for C2SP formats, so existing witness tooling can read ours. The `cosignature/v1` header and type 0x04 keep a cosignature from ever verifying as a note or receipt signature. The verifier must not import a service package. | 2026-10-27 |
| D39 | The `cosignature` table stores `(stream, tree_size, witness, line)`. It is insert-only, the first line per witness and size wins, and it has a foreign key to `checkpoint`. The line is verified before insert, before it is served and when it is verified offline. The export appends stored lines to each `checkpoints/*.note`, so bundle v1 is unchanged for readers that ignore unknown keys. | ARCHITECTURE's `checkpoint_id, witness_id, signature, ts`; a separate `cosignatures/` bundle member | The line already carries signature and time, so it is one authoritative value; split columns could disagree after an edit (as in D30). Cosigned notes are the C2SP-native shape and need no bundle version bump. | 2026-10-27 |
| D40 | The witness speaks C2SP tlog-witness at `POST /witness/v1/cosign`, the ARCHITECTURE path, and also at `/witness/v1/add-checkpoint`. A wrong old size gets `409` with `text/x.tlog.size`; other statuses are 400/403/404/422, with JSON error bodies. Its state is its own directory, one atomically replaced file per log, checked and saved under a lock, and re-verified on every read: `503 witness.state_invalid` if it does not verify. A log-signed checkpoint that fails the consistency check is saved as evidence and logged `CRITICAL`. Cosignature times never decrease. The key file must be mode 0600. `GET /witness/v1/latest` serves the last cosigned note for auditors to hold. | A JSON API; witness state in the ledger database; trusting saved state without re-verifying | Interoperable with tlog-witness clients. A witness that shares the operator's storage can be rolled back by the operator. The atomic check-and-save is the rollback-race rule in tlog-witness. Evidence plus the cosigned checkpoint is proof of misbehaviour (flow D step 4). | 2026-10-27 |
| D41 | After each checkpoint, the ledger asks every witness that has no stored cosignature for that size, concurrently, each with a timeout (5 s). It retries once from the size a `409` reports, and verifies every line under that witness's key before storing it. A checkpoint is final with `WITNESS_QUORUM` (2) distinct verified cosignatures. Without a quorum the checkpoint is still stored, and the loop reports `witness.no_quorum` in health. A witness ahead of the log is logged `CRITICAL` (`witness.ahead`). `checkpoints/latest?final=true` returns the latest final checkpoint. | Holding appends until final; stopping the loop on witness errors; trusting witness responses | A receipt is issued at append time (D11), so witness outages must not stop the ledger; finality is what downstream checks (claims, verifier) wait for. | D42 | `pl-verify --witness-keys FILE [--quorum N]` (default 2) reads C2SP cosigner verifier keys, one per line, from a file the auditor controls. Older checkpoints below quorum are counted but are not findings. Cosignature times are not checked, because the verifier is offline. `--quorum` without `--witness-keys` exits 2. | A directory of key files (ARCHITECTURE `keys/`); requiring a quorum on every checkpoint; reporting without failing | One text file in the standard verifier-key format is simplest to hand to an auditor. | D43 | Request-log middleware, size-limited body reads and the shared error handlers move from `ledger/api.py` to `common/http.py`, used by both the ledger and witness apps. `httpx` becomes a runtime dependency for the ledger's witness client. ## Anchors (step 7, Oct 28)

| ID | Decision | Rejected | Why | Date |
| --- | --- | --- | --- | --- |
| D44 | RFC 3161 tokens are parsed with `asn1crypto` and checked with `cryptography` in the pure `anchor/rfc3161.py`, which the verifier imports. The anchored digest is `SHA-256(checkpoint body)`. A token is accepted only if: the imprint matches; the content-type and message-digest signed attributes are right; an ESS signing-certificate attribute binds the signer certificate; the signature verifies (RSA PKCS#1 v1.5, ECDSA or Ed25519); the signer has a critical timeStamping EKU; and the chain reaches a trusted root with every certificate valid at `genTime`. Revocation is not checked. | `rfc3161ng` (ARCHITECTURE); OpenSSL `ts -verify` | `rfc3161ng` pulls `requests` and `pyasn1` into the offline verifier and does not do all of these checks. `asn1crypto` (MIT, pure Python, no network) only parses; the signature checks stay in `cryptography` (skill §4). OCSP and CRLs would need the network. | 2026-10-28 |
| D45 | O3 resolved: TSAs are DigiCert (`timestamp.digicert.com`) and FreeTSA (`freetsa.org/tsr`). Both are free and reachable, and they have independent roots. Their roots ship in `deploy/tsa/roots.pem` with fingerprints, for `pl-ledger` only; auditors bring their own `--tsa-roots`. Real tokens from both over the `checkpoint-v1` digest are test vectors (`rfc3161-published.json`), verified offline in every test run. | One TSA; trusting roots from the bundle | Two TSAs mean one that is down, wrong or colluding is not the only witness of time. The audited party never chooses the auditor's trust. Published tokens prove the verifier accepts real-world TSA output (three different signature setups were tested live; Sectigo also works with its root). | 2026-10-28 |
| D46 | OpenTimestamps proofs are read by our own `anchor/ots.py`. It supports only the SHA-256, append and prepend operations, and pending and Bitcoin attestations (others are reported as unknown). It has limits on size, depth and length, and requires https calendar URLs. The ledger submits the latest final checkpoint to `a.pool` and `b.pool` once per `OTS_INTERVAL_SECONDS` (an hour) and upgrades pending proofs only from `OTS_UPGRADE_CALENDARS`. Offline, a Bitcoin attestation is reported with its height and merkle root, not decided. | `opentimestamps-client` (ARCHITECTURE); following calendar URLs found in proofs; checking blocks via a public API | The client is LGPL and pulls in `python-bitcoinlib` and `GitPython`; the format is small. An unknown operation is refused rather than skipped (R4). Following URLs from proofs would let a calendar direct our requests (SSRF). The verifier must stay offline. | 2026-10-28 |
| D47 | The `anchor` table is `(stream, tree_size, kind, source, status, token, digest)` with a foreign key to `checkpoint`, insert-only: an upgraded OTS proof is a new `confirmed` row beside the `pending` one. Only final checkpoints are anchored, after witnessing. With TSAs configured and none answering, the loop reports `anchor.no_timestamp` (health), and the checkpoint stays stored. Bundle v2 adds `anchors/<size>-<kind>-<nn>.<tsr\|ots>` and `counts.anchors`; the reader still accepts v1. The API re-verifies anchors before serving them (`503 anchor.unverifiable`). | ARCHITECTURE's `checkpoint_id, kind, token, status` with "insert, then status updates"; anchoring every checkpoint | Insert-only keeps every proof any auditor may have seen (same reasoning as D30, D39). Anchoring an unwitnessed checkpoint would timestamp something the witnesses never backed. | 2026-10-28 |
| D48 | `pl-verify --tsa-roots FILE [--max-timestamp-lag S]` (default 3600). Every token must verify (`bad_timestamp`), and some checkpoint must be timestamped when there are records (`not_timestamped`). Backdating: for each record, the earliest trusted `genTime` of any checkpoint covering it may be at most `S` after the record's `ts` (`late_timestamp`), and not more than 300 s before it (`record_after_timestamp`). Anchors for checkpoints that are missing or that did not match are `anchor_without_checkpoint`. Without `--tsa-roots`, tokens are counted, never trusted. OTS proofs are always read (`bad_ots`). | Trusting any token that parses; checking only that timestamps exist | Timestamps only stop backdating if something compares them with what records claim. That comparison is the check that holds when the operator and every witness collude (ARCHITECTURE threat row). | 2026-10-28 |
